## 三、原生模块 node-pty

node-pty 含 C++ 源码，安装时按系统 Node ABI 编译；Electron 的 ABI 与系统 Node 不同，
必须针对 Electron 重编译，否则主进程 `require('node-pty')` 会抛 ABI 不匹配。

- 依赖：`node-pty@1.1.0`（desktop dependencies）、`@xterm/xterm@6.0.0`、`@xterm/addon-fit@0.11.0`；
  `@electron/rebuild@4.2.0`（devDependencies）。
- `pnpm-workspace.yaml` 的 `allowBuilds` 放行 `node-pty` 构建脚本。
- desktop `package.json` 增加 `"rebuild-native": "electron-rebuild -f -w node-pty"`，
  并挂到 `postinstall`（失败时 `|| echo skip native rebuild` 兜底，不阻断安装）。
- 显式重跑 `pnpm --filter @witseek/desktop rebuild-native` 输出 **Rebuild Complete**，
  产物 `node_modules/.pnpm/node-pty@1.1.0/.../build/Release/pty.node`（75,856 字节）已按 Electron 44 ABI 编译。
- 主进程做了**后端探测与降级**：`terminal.ts` 动态探测 node-pty，缺失时在 Linux 回退到
  util-linux 的 `script -qec 'stty rows..; exec bash -l' /dev/null` 伪终端；两种后端都把
  `cwd` 在主进程侧锁定为工作区，渲染层无法逃逸。界面终端栏显示当前后端名（实测为 `node-pty`）。

## 五、实现与设计的差异

DESIGN.md §8.4 曾设想检查点用「git stash 或文件副本」二选一。最终采用**文件副本快照**，
不依赖 git：

- 演示工作区与用户真实工作区都不保证是 git 仓库，引入 git 会在非仓库目录直接失效；
- 快照存于 `userData/checkpoints/<id>/`，保存文件副本 + `manifest.json`（相对路径、sha256、大小、mtime）；
- **护栏**：单文件 > 5MB、快照总量 > 200MB、文件数 > 3000 时跳过/修剪，最多保留 10 个检查点；
- 回滚按清单还原被跟踪文件，并在回滚前先打一个 `rollback-backup` 快照，保证回滚本身也可撤销；
- 检查点服务与设置存储都不依赖 Electron（纯 Node + fs），可在内核层单测。

## 六、本阶段逮到并修复的真实缺陷

| 缺陷 | 表现 | 根因与修法 |
| --- | --- | --- |
| 主进程 `Identifier 'require' has already been declared` | dev 一启动主进程即崩溃，只渲染出空白/旧界面 | electron-vite 的 ESM 主产物自带 `require` 垫片，`terminal.ts` 里再 `const require = createRequire(...)` 重复声明。改名为 `nodeRequire`（typecheck 抓不到，只有运行 ESM 才暴露） |
| 终端折叠时 xterm 画布溢出 | 折叠成一行后，黑色终端内容仍从栏下方漏出 | `.terminal` 容器缺 `overflow:hidden`，31px 折叠高度裁不掉 body。补上裁剪 |
| 漏跑 tests 脚手架导致 `tsc: command not found` | 首次部署后 typecheck/vitest 二进制消失 | `scaffold_p1.sh` 写的是精简根 `package.json`，devDeps 与 test 脚本由 `scaffold_p2_tests.sh` 补；只跑 p1/p2/p3/p4 会把根 `package.json` 覆盖成无 devDeps 版。**重建必须按序包含 p2_tests / p3_tests**，随后 `pnpm install --no-frozen-lockfile` |
| 检查点回滚路径计算 | 回滚到含 `..` 的目标时路径拼接错误 | `join(abs, '..')` 改为 `dirname(abs)`（由 `checkpoint.test.ts` 逮到） |
| 回滚前备份被修剪逻辑误删 | 回滚动作自身的 rollback-backup 可能被 prune 清掉 | 建回滚备份时传 `skipPrune`，备份完成后再统一修剪（由测试逮到） |
| 两处 TS6133 未用变量 | typecheck 失败 | `diff-hunks.test.ts` 解构出的未用变量删除 |

## 七、无头 GUI 自动化（本阶段验证通路）

服务器无显示器，P3 曾把 `xdotool` 用户态解包到 `.tools/xdotool/prefix/usr/bin/xdotool`
（不在 PATH，需带完整路径与 `LD_LIBRARY_PATH`，见 P3 验收记录）。

本阶段该二进制仍在；另外验证了一条**纯 Python 备用通路**（不依赖解包 deb）：

```bash
# conda 环境内（无需 sudo，纯 Python 包）
~/miniconda3/envs/xwt_seek/bin/python -m pip install python-xlib
# 驱动脚本 scripts/xdrive.py：windows / click x y / type TEXT / key NAME / sleep SEC
~/miniconda3/envs/xwt_seek/bin/python scripts/xdrive.py click 352 149
```

关键经验：

1. **坐标不要目测**：截图缩放到 1400 宽后目测误差可达 40px 以上（终端栏实测在 y≈879，目测成 821）。
   本阶段改用 PIL 读原始 1920×1080 截图、按控件填充色程序化定位行范围再取中心。
2. openbox 下窗口首次合成点击可能只用于聚焦、不触发控件；切换页签这类幂等操作可双重点击，
   但**折叠/展开类 toggle 不能点两次**（会展开又收起）。
3. 键盘事件经 XTest 投递后，需先让目标控件获得焦点：HTML input 点击即聚焦；
   xterm.js 的隐藏 textarea 需点在终端**文本行**上才稳定聚焦，点空白行可能不聚焦。
4. python-xlib 0.33 的 `fake_input` 只接受 `(display, type, code, x, y, delay)` 位置参数，
   无 `is_absolute`/`mv_x` 形参；移动指针改用 `Xlib.protocol.request.WarpPointer`
   （字段名 `src_window/dst_window/.../dst_x/dst_y`）。
