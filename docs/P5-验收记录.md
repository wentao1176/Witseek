## 二、技术路线（为什么不用 electron-builder 自带 NSIS）

服务器约束：无 sudo、`which wine wine64 makensis 7z` 全空、未启用 i386 多架构。

electron-builder 在 Linux 上打 Windows NSIS 的两个原生环节都依赖 Wine：

1. **rcedit**（改写 exe 图标/版本）—— 通过 `win.signAndEditExecutable: false` 跳过，
   改在 `afterPack` 钩子里用纯 JS 的 **resedit 3.1.0** 直接改写 PE 资源；
2. **NSIS 编译**——electron-builder 下载的 `nsis-3.0.4.1` 内 `makensis.exe` 是
   **32 位 PE**（实测 `PE32 ... Intel 80386`），由 electron-builder 经 `spawn wine` 运行；
   实测报错 `wine process failed ENOENT ... spawn wine ENOENT`。32 位 Wine 需 i386 依赖树，
   无 sudo / 未 add-architecture 无法获取。

最终采用**两段式、全免 Wine** 路线（`scripts/pack_windows.sh`）：

```
 electron-vite build                 编译 main/preload/renderer 到 apps/desktop/out
        │
 electron-builder --win dir          下载 win32-x64 Electron、组 win-unpacked
        │                             （signAndEditExecutable:false，不跑 rcedit）
 afterPack.cjs（resedit 3.1.0）       改写 Witseek.exe 的图标组 + VS_VERSIONINFO
        │
 make_nsis.py                        遍历 win-unpacked 生成零第三方插件的 witseek.nsi
        │
 conda-forge nsis 3.11 的            Linux ELF makensis，lzma solid 编译
        │                             （约 4 分钟）
        ▼
 Witseek-Setup-0.1.0.exe
```

关键：NSIS 的 `makensis` 本质是**编译器**，输出 Windows PE 安装程序，与运行平台无关；
conda-forge 提供 Linux 原生构建（`.../envs/xwt_seek/NSIS/bin/makensis` 为
`ELF 64-bit LSB pie executable, x86-64`）。自写 `.nsi` **只使用 NSIS 内置指令与 MUI2**
（`File` / `CreateShortcut` / `WriteUninstaller` / `WriteRegStr` / 内置 lzma），
不引用任何在 Linux makensis 下无法加载的 Windows 插件 DLL，因此可在 Linux 正常编译。

## 五、node-pty 的 Windows 原生模块

node-pty@1.1.0 的 npm 包自带 **prebuildify 风格、全平台、N-API** 的预编译二进制
（目录名无 ABI 后缀即 N-API，跨 Node/Electron ABI）。win32-x64 一套已全部进包
（`resources/app.asar.unpacked/node_modules/node-pty/prebuilds/win32-x64/`）：

```
pty.node  conpty.node  conpty_console_list.node   # N-API 原生模块
winpty-agent.exe  winpty.dll
conpty/OpenConsole.exe  conpty/conpty.dll          # Windows Pseudo Console
```

- 校验：`find ... -name '*.node' -exec file` 中**无任何 ELF**（Linux 编译产物未混入）。
- 意义：Windows 安装后，P4 的集成终端可走 node-pty 的 ConPTY/WinPTY 后端，
  无需在 Windows 上现场编译原生模块。
- 说明：N-API 二进制在 Electron 44 下的实际加载，仍以 Windows 实机运行为准（见 §九）。

## 六、安装器行为（witseek.nsi）

由 `scripts/make_nsis.py` 按 win-unpacked 实际文件（130 个 / 16 个目录）逐目录生成
`SetOutPath` + `File`，无手写文件清单、不会漏文件或带入多余文件：

- **MUI2 向导**：欢迎页 → 安装目录页 → 组件页 → 安装进度页 → 完成页（完成页可勾选立即启动）；
  卸载向导含确认页与进度页。语言：简体中文 + English。
- **per-user 安装、免 UAC**：`RequestExecutionLevel user`，默认目录
  `$LOCALAPPDATA\Programs\Witseek`，可用目录页更改；不需要管理员权限。
- **组件**：核心文件（必选，SectionIn RO）+ 可选"桌面快捷方式"（默认勾选，组件页可取消）。
- **快捷方式**：开始菜单 `Witseek/Witseek.lnk` 与 `卸载 Witseek.lnk`；可选桌面快捷方式；
  快捷方式图标指向 `Witseek.exe`。
- **卸载**：生成 `Uninstall Witseek.exe`；写 HKCU
  `Software\Microsoft\Windows\CurrentVersion\Uninstall\Witseek`（DisplayName / DisplayVersion /
  Publisher / InstallLocation / DisplayIcon / UninstallString / QuietUninstallString(`/S`) /
  NoModify / NoRepair），出现在"设置-应用"里；卸载删除安装目录、快捷方式与注册表项。
- **压缩**：`SetCompressor /SOLID lzma`，386 MiB 未打包目录压缩为 112 MiB 安装包。
- **图标/版本**：安装器与卸载器图标用多尺寸 `icon.ico`；`VIProductVersion/VIFileVersion=0.1.0.0`，
  中英文 `VIAddVersionKey`。
- DPI 感知：`ManifestDPIAware true`。

## 九、本阶段踩过的坑（已修复，勿重复）

| 坑 | 表现 | 根因与修法 |
| --- | --- | --- |
| resedit 3.x 图标入参 | `icon.isIcon is not a function` | `Data.IconFile.from(ico).icons` 元素是 `{...meta,data:IconItem}` 包装，真正图标在 `.data`；需 `icons.map(i=>i.data)` 再传给 `IconGroupEntry.replaceIconsForResource` |
| resedit 3.x 无 `setResource` | `exe.setResource is not a function` | 3.x 改为资源对象 `res.outputResource(exe)` 写回，再 `exe.generate()`；版本信息用 `vi.outputToResourceEntries(res.entries)` |
| resedit 是纯 ESM | afterPack 是 `.cjs` 无法 require | 钩子里用动态 `await import('resedit')` |
| `VIFileVersion` 段数 | `invalid VIFileVersion format, should be X.X.X.X` | 必须四段；`0.1.0` 由 make_nsis.py 补零为 `0.1.0.0` |
| `VIAddVersionKey` 选项位置 | `Invalid command: "/LANG=2052"` | `/LANG=` 必须跟在命令名**之后**：`VIAddVersionKey /LANG=2052 "K" "V"` |
| electron-builder NSIS 需 Wine | `spawn wine ENOENT` | 其 makensis.exe 是 32 位 PE，需 wine32（i386）；改用 conda-forge Linux 原生 makensis + 自写零插件 nsi |
| rcedit 依赖 Wine | 打包在"updating executable resource"附近失败 | `win.signAndEditExecutable:false` 跳过，resedit afterPack 替代 |
